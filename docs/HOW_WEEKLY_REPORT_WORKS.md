# How Weekly Report Works

## Overview

**File:** `employee/weekly_report.php`  
**Type:** Payroll & Deployment Report Page  
**Access:** Admin, Super Admin, Developer only

This page displays worker payroll data for a selected week or month. It does **NOT reset every day** - it shows accumulated data based on the selected time period.

---

## Data Persistence

### Does it reset every day? **NO**

The report shows **accumulated data** for the selected period:
- **Weekly View:** Shows all days worked in the selected week (Week 1-5)
- **Monthly View:** Shows all days worked in the entire month

The data persists because it comes from:
1. `daily_payroll_reports` table - Pre-calculated daily records
2. `attendance` table - Raw time-in/time-out records (fallback)
3. `weekly_payroll_reports` table - Saved allowances and payment status

## Data Calculation

### Date Range Selection

**Weekly View:**
- Week 1: Days 1-7 of month
- Week 2: Days 8-14 of month
- Week 3: Days 15-21 of month
- Week 4: Days 22-28 of month
- Week 5: Days 29+ (if month has >28 days)

**Monthly View:**
- Shows all days in selected month (1-31)

### Days Worked Calculation

```php
// From function/report.php

// Scenario 1: Single branch per day
if (count($branches) === 1) {
    $payroll['days_worked'] += 1.0;  // 1 day
}

// Scenario 2: Two branches (transfer)
if (count($branches) === 2) {
    // 0.5 day per branch
    foreach ($branches as $bName => $bData) {
        $payroll['_branches'][$bName]['days'] += 0.5;
    }
    $payroll['days_worked'] += 1.0;  // Total still 1 day
}
```

**Important:** Multiple time entries in one day still count as **1 day total**, not 2.

## Cron Job Data Generation

### Daily Calculation (Midnight)
**Script:** `employee/cron/daily_payroll_calculation.php`

Runs every day at midnight to:
1. Calculate payroll for "yesterday"
2. Save to `daily_payroll_reports` table
3. Includes: days_worked, hours, OT, gross_pay

### Weekly Aggregation (Friday/Saturday)
**Scripts:** 
- `weekly_aggregate_non_branch33.php` (Friday midnight)
- `weekly_aggregate_branch33.php` (Saturday midnight)

Aggregates daily records into `weekly_payroll_reports` for the week.

## What Gets Reset vs What Persists

### ✅ Persists (Saved to Database)
| Data | Storage | Notes |
|------|---------|-------|
| Performance Allowance | `weekly_payroll_reports` | Saved per week/month |
| Payment Status | `weekly_payroll_reports` | "Paid" / "Not Paid" |
| Attendance Records | `attendance` | Permanent time logs |
| Daily Payroll | `daily_payroll_reports` | Cron-generated |

### 🔄 Resets/Recalculated
| Data | Behavior |
|------|----------|
| Gross Pay | Recalculated from days × rate |
| Deductions | Recalculated per week |
| Cash Advance | Manual entry (resets to 0) |

## Allowance System

### How It Works

```
Week 1 Report Load:
         │
         ▼
┌────────────────────────┐
│ Check weekly_payroll   │
│ _reports table         │
│ for saved allowance    │
└────────────────────────┘
         │
    ┌────┴────┐
    │         │
Found       Not Found
    │         │
    ▼         ▼
Use saved   Default to 0
value       (or employee
            default if
            implemented)
```

### Allowance Persistence
- **Saved to:** `weekly_payroll_reports` table
- **Key:** (employee_id, year, month, week_number, view_type)
- **When saved:** When admin changes the value and it auto-saves via AJAX
- **Persists across:** Page refreshes, different sessions
- **Does NOT persist to:** Next week (each week is separate)

---

## Page Refresh Behavior

### What happens when you refresh?

1. **Same Week Selected:**
   - Loads saved allowances from `weekly_payroll_reports`
   - Recalculates payroll from `daily_payroll_reports`
   - Shows updated totals

2. **Different Week Selected:**
   - Loads that week's specific data
   - Allowances may be different (per-week storage)

3. **New Data Available:**
   - If cron jobs ran since last visit
   - New attendance data appears
   - Calculations update automatically

---

## Key Takeaways

1. **Data is persistent** - stored in database tables, not session-based
2. **Report shows accumulated totals** - not just "today"
3. **Allowances are per-period** - Week 1 allowance ≠ Week 2 allowance
4. **Days don't double-count** - 2 entries in 1 day = 1 day worked
5. **Cron jobs pre-generate data** - Report mostly displays, not calculates
