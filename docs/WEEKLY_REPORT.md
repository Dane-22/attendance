# Weekly Report Documentation

## Overview

**File:** `employee/weekly_report.php`  
**Logic File:** `employee/function/report.php`  
**Type:** Admin Payroll & Deployment Report  
**Access:** Admin, Super Admin, Developer roles only

This module generates payroll reports for worker-position employees with two view modes:
- **Weekly View:** Shows payroll data for a specific week (1-5) of a month
- **Monthly View:** Shows aggregated payroll data for the entire month

---

## Data Sources

The report pulls data from two primary sources:

### 1. `daily_payroll_reports` Table (Primary)
- Pre-calculated daily payroll records
- Contains: days_worked, hours, OT, deductions, allowances per day
- Used when available for the date range

### 2. `attendance` Table (Fallback)
- Raw time-in/time-out records
- Calculates hours worked from timestamps
- Only used if no `daily_payroll_reports` record exists for that date

---

## Days Worked Calculation Logic

### Key Question: How are days counted when worker has multiple entries?

**Scenario 1: Single Branch per Day**
- If worker clocks in/out at one branch in a day = **1 day counted**
- Hours are summed from time_in to time_out

**Scenario 2: Two Branches per Day (Transfer)**
```php
// report.php:333-349
if (count($branches) === 2) {
    foreach ($branches as $bName => $bData) {
        $payroll['_branches'][$bName]['days'] += 0.5;  // 0.5 day each
        // ...
    }
    $payroll['days_worked'] += 1.0;  // Total = 1 day
}
```
- Worker at 2 branches same day = **0.5 day per branch, 1 day total**
- This handles transfers between branches

**Scenario 3: Default Case**
```php
// report.php:354
$payroll['days_worked'] += 1.0;
```
- Any timed-out attendance = **1 day counted per date**

### Answer to Common Question:
> **Q:** If worker time is 2 in one day, does it count 2 days?  
> **A:** **NO** - Multiple entries in one day still count as 1 day total. If at 2 branches, it's split 0.5 + 0.5 = 1 day.

## Payroll Calculation

### Earnings
- **Basic Pay:** `daily_rate × days_worked`
- **Overtime:** `OT hours × (daily_rate / 8)`
- **Performance Allowance:** Editable input, saved to database
- **Gross Pay:** Basic Pay + OT + Allowance

### Deductions
| Type | Weekly (Weeks 1-3) | Week 4 | Monthly |
|------|-------------------|--------|---------|
| SSS | ₱150.00 (450/3) | ₱0 | ₱450.00 |
| PhilHealth | ₱83.33 (250/3) | ₱0 | ₱250.00 |
| Pag-IBIG | ₱66.67 (200/3) | ₱0 | ₱200.00 |

**Note:** Deductions are only applied if employee has attendance records (`days_worked > 0`).

## Features

### Filters
- **Month Selector:** Choose from last 12 months
- **Week Selector:** Weeks 1-4 (or 5 if month has >28 days)
- **Branch Filter:** Quick filter with pagination (10 branches per page)
- **Search:** Filter by employee name

### Interactive Elements
- **Performance Allowance Input:** Auto-saves on change
- **Cash Advance Input:** Manual entry for deductions
- **Payment Status:** "Paid" / "Not Paid" dropdown with visual styling
- **Payslip Modal:** Generates printable payslip with signature lines
- **Export to Excel:** Downloads report as XLSX file

### Branch Pagination
When many branches exist (>10), pagination controls allow navigating through branch filter options without overwhelming the UI.

## Cron Job Integration

Report data is pre-generated by scheduled cron jobs:
- `weekly_aggregate_non_branch33.php` - Runs Friday midnight
- `weekly_aggregate_branch33.php` - Runs Saturday midnight

On-demand saving is currently disabled (commented out at line 510-512 in report.php).
