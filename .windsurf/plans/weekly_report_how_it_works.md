# How weekly_report.php Works

## Overview
The `weekly_report.php` page displays payroll data for workers across weekly, monthly, or custom date ranges. It serves as the primary payroll reporting interface for administrators.

## Architecture

### File Structure
```
employee/weekly_report.php       - Main UI/display file
employee/function/report.php     - Data processing logic (included by weekly_report.php)
employee/cron/daily_payroll_calculation.php  - Cron job that populates data
```

## Data Flow

### 1. Data Source Priority
The report uses a **two-tier data source** approach:

**Primary Source: `daily_payroll_reports` table**
- Pre-calculated payroll data generated by cron jobs
- Contains: days_worked, total_hours, ot_hours, gross_pay, deductions, etc.
- Located at: `employee/cron/daily_payroll_calculation.php`

**Fallback Source: `attendance` table**
- Raw clock-in/out data
- Only used for dates NOT covered by daily_payroll_reports
- Requires BOTH `time_in` AND `time_out` to count a day

### 2. How Days Are Counted

#### From `daily_payroll_reports` (Primary):
```php
// function/report.php:377
$employee_payroll[$emp_id]['days_worked'] += floatval($row['days_worked'] ?? 0);
```
- Uses the pre-calculated `days_worked` value
- This value was computed during the nightly cron job

#### From `attendance` table (Fallback):
```php
// function/report.php:431-436
$time_in = $row['time_in'] ?? null;
$time_out = $row['time_out'] ?? null;
if (empty($time_in) || empty($time_out)) {
    continue;  // SKIP records without BOTH times
}
```

**Key Rule**: A day only counts if BOTH clock-in AND clock-out exist.

### 3. Multi-Record Per Day Handling

When an employee has multiple clock-in/out records on the same day (e.g., transferred branches):

```php
// function/report.php:471-631
// 1. Merge records within 15-minute threshold
// 2. If exactly 2 branches with gap > 15 min: count as 0.5 day each
// 3. Otherwise: count as 1 day total, assign to primary branch
```

### 4. Week Calculation Logic

```php
// function/report.php:50-121
// Work days only (excludes Sundays)
for ($day = 1; $day <= $days_in_month; $day++) {
    $date_str = sprintf('%04d-%02d-%02d', $year, $month, $day);
    $day_of_week = date('w', strtotime($date_str));
    if ($day_of_week != 0) { // Exclude Sundays
        $work_days[] = $day;
    }
}
```

**Week Boundaries**:
- Week 1: From 1st work day up to first Sunday (or max 5 days)
- Weeks 2-4: Monday to Friday (5 days each)
- Week 5: Only if month has >28 days

### 5. Deduction Calculation

**Monthly View**:
```php
$sss_deduction = 450.00;
$philhealth_deduction = 250.00;
$pagibig_deduction = 200.00;
```

**Weekly View** (Prorated by week):
| Week | SSS | PhilHealth | Pag-IBIG |
|------|-----|------------|----------|
| 1    | 250 | 100        | 50       |
| 2    | 100 | 100        | 50       |
| 3    | 100 | 50         | 100      |
| 4-5  | 0   | 0          | 0        |

### 6. Payroll Calculation Formula

```php
// function/report.php:645-674
$daily_rate = $payroll['daily_rate'];
$days_worked = $payroll['days_worked'];

// Gross pay
$gross_pay = $daily_rate * $days_worked;

// Deductions (only if has_deduction flag is set AND days_worked > 0)
if ($days_worked > 0 && !empty($payroll['employee']['has_deduction'])) {
    $payroll['sss_deduction'] = $sss_deduction;
    $payroll['philhealth_deduction'] = $philhealth_deduction;
    $payroll['pagibig_deduction'] = $pagibig_deduction;
}

// Net pay
$net_pay = $gross_pay - $payroll['total_deductions'];
```

## Data Freshness

### Cron Job Schedule
```php
// daily_payroll_calculation.php runs nightly via cron
// Processes previous day's attendance
$yesterday = date('Y-m-d', strtotime('-1 day'));
```

### Real-time Fallback
If cron data doesn't exist for a date, the report falls back to calculating from raw attendance in real-time (slower but ensures data availability).

## Validation Triggers

The system has database triggers to prevent orphaned payroll records:

```sql
-- create_validation_trigger.php
CREATE TRIGGER trg_validate_attendance_before_dpr_insert
BEFORE INSERT ON daily_payroll_reports
FOR EACH ROW
BEGIN
    DECLARE v_attendance_count INT;
    
    SELECT COUNT(*) INTO v_attendance_count
    FROM attendance
    WHERE employee_id = NEW.employee_id
      AND attendance_date = NEW.report_date
      AND time_in IS NOT NULL
      AND time_out IS NOT NULL;
    
    IF v_attendance_count = 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Cannot insert without valid attendance';
    END IF;
END
```

## Common Issues

### Issue 1: Missing Clock-outs
If an employee clocks in but doesn't clock out:
- `daily_payroll_reports`: No record created (validation fails)
- `weekly_report.php`: Day not counted (filtered by time_out check)
- `audit.php` calendar: Shows as "Clocked In Only" (only requires time_in)

### Issue 2: Cron Job Lag
If the nightly cron fails:
- Report falls back to real-time calculation
- May show slightly different numbers until cron catches up

### Issue 3: Multi-Branch Days
Employee works at 2 branches same day:
- Counted as 1 day total in days_worked
- Split 0.5/0.5 between branches if large time gap
- Assigned to primary branch (most hours) if small gap
